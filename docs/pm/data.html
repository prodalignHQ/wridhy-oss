🔒 Data & Privacy

MoMoney's privacy-first design principles and data portability guarantees

Privacy Principles

MoMoney is built on an explicit privacy-first philosophy. Financial data is sensitive — MoMoney treats it that way by making non-storage the default, not an advanced setting.

Core Rules

  • Financial data is not stored by default — it exists only in the browser session
  • Users must explicitly opt-in to cloud persistence (not buried in settings — requires active consent)
  • Users can export their data at any time in portable formats
  • Users can delete all stored data at any time with no penalty

Authentication

Authentication is only required when using cloud persistence mode. Users can use the app in session mode without creating an account.

Current Auth Methods

  • Email + password signup
  • Email verification required
  • Login / Logout
  • Password reset

Future Auth Methods

  • Sign in with Google
  • Sign in with Apple
Planned

Data Portability

Users own their data. MoMoney supports export in three formats:

🗄️

SQLite

A complete database file with all transactions, accounts, categories, rules, invoices, and net worth entries. Can be re-imported to run MoMoney locally.

📄

CSV

A flat spreadsheet export of all transactions. Suitable for import into Excel, Google Sheets, or other finance tools.

{ }

JSON

A structured JSON export of all data. Developer-friendly format for building custom tooling on top of your financial data.

Security

RequirementDetails
Encrypted StorageFinancial data encrypted at rest when cloud persistence is enabled
Secure AuthPassword hashing, session tokens, email verification
Data IsolationStrict per-user data isolation — no cross-user data access possible
No Third-Party SharingFinancial data is never shared with third parties or used for ads

Performance Requirements

MoMoney is designed to scale with heavy personal use without degrading the experience.

Scale Targets

  • 100,000+ transactions per user
  • Analytics queries under 1 second
  • 1,000,000 registered users (system level)
  • 10,000,000+ total transactions (system level)

Architecture Choices That Enable This

  • PostgreSQL with indexed queries
  • Drizzle ORM for type-safe, efficient queries
  • Hono.js lightweight API backend
  • Deduplication hashing to prevent data bloat
