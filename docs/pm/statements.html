📥 Statement Import

How users bring their bank data into MoMoney — without manual entry

Overview

Statement Import is the primary entry point for financial data. Users download a statement from their bank's online portal and upload it to MoMoney. The system parses the file, extracts structured transaction data, shows a preview, and — after the user confirms — imports the transactions into their account.

Parser Architecture

The parser system is designed as a registry — each bank + format combination is a separate parser plugin. Adding support for a new bank requires writing a parser that conforms to the shared BankParser interface.

Statement Tagging

Every statement must be tagged to a statement month (e.g., March 2025). This is a required step — it's how statements are grouped into monthly invoices later.

Why Tagging Matters

  • Statements tagged to the same month can be combined into a single invoice
  • Multiple statements from different banks/accounts can share the same month tag
  • The tag drives all month-based analytics and invoice generation

Duplicate Prevention

🔑 Automatic Deduplication

Each transaction is assigned a deterministic hash based on: account ID + date + amount + description. If an identical transaction already exists in the database, it is automatically skipped during import. The import summary shows exactly how many transactions were imported vs. skipped as duplicates.

Financial Accounts

Before uploading a statement, users must have a financial account set up. Accounts represent the source of the statement (e.g., "ICICI Savings", "ICICI Credit Card").
